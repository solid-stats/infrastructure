# Phase 21.1: Code Review Report

**Reviewed:** 2026-08-24T19:17:24Z
**Depth:** standard
**Files Reviewed:** 3
**Status:** issues_found

## Summary

The submitted implementation does not safely reach materialization. Five
blocking contract defects remain: the old Phase 21 apply and behavior-probe
surfaces were silently changed, both new live validators disagree with the
pinned MemPalace v3.5.0 contract, and the approved correction validator omits
the required inventory immutability gates. The focused tests pass because
their fixtures reproduce the implementation's invented schemas rather than
the pinned server response.

## Critical Issues

### CR-01: Initial Phase 21 apply path now grants the Phase 21.1 update capability

**Classification:** BLOCKER

**File:** `scripts/configure-solidstats-memory-client.py:37`

**Issue:** `ENABLED_TOOLS` was changed globally from the Phase 21 seven-tool
surface to the eight-tool successor. The pre-existing `apply`, `validate`,
`rollback`, retirement, and recovery paths continue to consume that same
constant (`apply` renders it at lines 624-628 and `inspect_policy` validates it
at lines 388-394). Consequently, an initial Phase 21 materialization now grants
`mempalace_update_drawer` directly and bypasses the new predecessor-only
upgrade contract. This breaks the locked requirement that the initial apply
path remain separate and backward compatible.

**Fix:** Keep a dedicated immutable Phase 21 allowlist for all existing
apply/validate/rollback/retirement paths. Use a separate Phase 21.1 successor
constant only inside the four upgrade commands. Restore the pre-existing tests
to seven-tool expectations and add new successor-only assertions without
rewriting historical behavior.

### CR-02: Phase 21 behavior evidence was silently redefined as an eight-tool probe

**Classification:** BLOCKER

**File:** `scripts/probe-solidstats-memory.py:40`

**Issue:** `REQUIRED_TOOLS` now includes `mempalace_update_drawer`, and the
existing `probe_behavior_matrix` uses it to gate availability and compute the
schema digest at lines 975-980 and reports a required count of eight at line
1082. That function is part of the sealed Phase 21 behavior/evidence path, not
the new fresh-client checkpoint. Re-running the Phase 21 probe now produces a
different digest and contract, so old recovery evidence is no longer
reproducible and the supposedly immutable Phase 21 path has been altered.

**Fix:** Restore the original seven-tool Phase 21 constant and behavior digest.
Introduce a distinct eight-tool `CURATOR_CLIENT_TOOLS` constant used only by
`validate_client_tool_surface` and Phase 21.1 evidence.

### CR-03: Fresh-client schema validator rejects the actual pinned v3.5.0 schema

**Classification:** BLOCKER

**File:** `scripts/probe-solidstats-memory.py:54`

**Issue:** `UPDATE_TOOL_SCHEMA` requires `"additionalProperties": false`, but
the pinned MemPalace v3.5.0 `mempalace_update_drawer` input schema contains
only `type`, `properties`, and `required`; it does not declare
`additionalProperties`. Because line 632 requires exact mapping equality, the
mandatory fresh-session gate will reject the real Codex-loaded schema. The
test at `tests/test-memory-cutover-contract.py:2144` passes only because it
constructs the same non-server field locally.

**Fix:** Copy the exact pinned v3.5.0 schema shape into the constant, including
the real property descriptions if the Codex tool surface preserves them, and
test against a captured/checked-in value-free schema fixture derived from the
pinned server definition rather than a hand-written mirror.

### CR-04: Read-back rejects real drawer payloads

**Classification:** BLOCKER

**File:** `scripts/probe-solidstats-memory.py:641`

**Issue:** `_exact_drawer_payload` requires exactly
`drawer_id/content/room/provenance/metadata` and rejects every other key. The
pinned v3.5.0 `tool_get_drawer` response instead returns top-level
`drawer_id/content/wing/room/metadata`, has no top-level `provenance`, and may
also return `chunks` and `chunk_ids` for a chunked drawer. Therefore both the
disposable UAT and approved correction paths fail before mutation against the
real server. Tests at lines 2251-2259 and 2320-2330 invent the implementation's
five-field payload and cannot catch the incompatibility.

**Fix:** Validate the exact pinned `_drawer_payload` union: require the five
base fields with top-level `wing`, allow the two chunk fields only as a
consistent pair, and preserve/compare the complete returned object. Treat
provenance as metadata fields actually present in the returned metadata rather
than inventing a top-level field. Build tests from pinned v3.5.0 unchunked and
chunked response fixtures.

### CR-05: Correction omits inventory immutability

**Classification:** BLOCKER

**File:** `scripts/probe-solidstats-memory.py:675`

**Issue:** `validate_approved_correction` compares only one before/after drawer
object and its update arguments. It accepts without receiving or checking the
pre/post inventories, so it cannot prove that the old `infrastructure` wing is
empty, the approved drawer exists exactly once in `devops/operations`, or
archive and unrelated drawers stayed byte-identical. Those are explicit
acceptance invariants and review priorities. The corresponding test at lines
2319-2386 likewise contains no inventory controls.

**Fix:** Add an aggregate correction validator that accepts private pre/post
inventory snapshots, verifies exact approved-ID membership and locations,
requires an empty old active wing, and compares complete archive/unrelated
inventories. Return only booleans/counts/digests through the public evidence
allowlist, and add negative tests for each independently mutated inventory.

## Warnings

### WR-01: Upgrade duplicates the transaction state machine

**Classification:** WARNING

**File:** `scripts/configure-solidstats-memory-client.py:398`

**Issue:** Roughly 195 lines add parallel registration validation, policy
parsing, rendering, private-state metadata, validation, apply, and rollback
functions beside the existing implementations. The duplicated paths have
already drifted: the old functions consume the successor constant while the
new functions distinguish predecessor/successor. This maintenance split is
disproportionate for an append-only allowlist transition and directly enabled
CR-01.

**Fix:** Extract one exact-policy classifier/renderer and one accepted-state
transaction primitive parameterized by predecessor and successor tuples. Keep
thin initial-apply and upgrade commands with separate explicit contracts.
