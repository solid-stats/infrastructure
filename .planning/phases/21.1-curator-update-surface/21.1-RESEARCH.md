### Locked Decisions

#### Exact Client Surface

- The successor `ENABLED_TOOLS` tuple is exactly the seven Phase 21 tools plus
  `mempalace_update_drawer`.
- Narrow forbidden-tool validation only enough to permit that exact tool.
  Tunnels, KG, diary, checkpoint, mine, sync, hooks, admin methods, bulk
  deletion, and unrelated mutation tools remain forbidden.
- Treat the existing seven-tool policy as the only valid predecessor, the
  eight-tool policy as the idempotent successor, and any other configured
  surface as fail-closed drift.
- Preserve the existing atomic client-config replacement and rollback
  transaction; Phase 21's initial no-policy materialization path is not reused
  as the upgrade contract.

#### UAT and Approved Correction

- A disposable drawer may use only a `uat-<nonce>` room. Acceptance requires
  add, exact-ID read, update, exact-ID read-back, and exact-ID deletion, followed
  by proof that no disposable drawer remains.
- For drawer `drawer_infrastructure_operations_234ea02816667f903010e583`, first
  verify wing `infrastructure` and room `operations`, then change only its wing
  to `devops`.
- On read-back, drawer ID, content, room, provenance, and every metadata field
  except `metadata.wing` must be byte/value-equivalent to the pre-update state.
  The old active `infrastructure` wing must then be empty.
- Never update, delete, move, or reclassify an archive drawer. Do not substitute
  another drawer or expand the approved correction batch.

#### Materialization Boundary

- Apply only the Codex client policy on home Ubuntu. Do not restart or redeploy
  Qdrant, MemPalace, Kubernetes, nginx, or the VPS, and do not repeat Phase 21
  reboot, restore, cutover, or runtime rollback drills.
- A fresh Codex session is a mandatory gate after client policy materializes
  because the MCP tool surface is loaded at session start.
- Windows materialization stays on the existing Windows/shared-config path.
  Record an explicit follow-up without editing `~/.agents` in this phase.
- Temporary Linux/Windows contract drift is accepted until that follow-up is
  applied. The final managed SolidStats memory contract remains out of scope.

#### Health Cleanup

- Retain the stale Phase 21 worktree lock under the private-artifact protocol
  before removing the clean stale worktree. Preserve its branch.
- Archive the stale tracked `.planning/.continue-here.md` under the milestone
  archive instead of deleting its history.

### the agent's Discretion

- The agent may choose exact test decomposition, evidence schemas, and the
  durable private-artifact location while meeting all fail-closed, atomicity,
  cleanup, and provenance invariants above.

### Deferred Ideas (OUT OF SCOPE)

- Materialize the same policy through the existing Windows/shared-config path.
- Reconcile the final managed SolidStats memory contract only when that owning

## Summary

Phase 21.1 should be planned as two separately gated changes: an offline, atomic transition of the machine-local Codex allowlist from one exact state to another, followed only in a fresh Codex session by live client-surface and exact-ID mutation evidence. The current implementation accepts either no policy before initial application or the exact current policy during validation; it does not yet model a seven-tool predecessor and eight-tool successor upgrade. [VERIFIED: scripts/configure-solidstats-memory-client.py:366-449] The existing atomic exchange, lock, read-back, token-subtree validation, and rollback machinery must remain the transaction substrate rather than being replaced. [VERIFIED: scripts/configure-solidstats-memory-client.py:58-114,184-311,623-637]

The live portion must not use raw MemPalace `tools/list` as proof of the client-filtered surface. The current raw protocol probe enumerates the server's tools directly, while the locked decision states that the fresh-session `solidstats_memory` namespace is the authority for client-side exclusion. [VERIFIED: scripts/probe-solidstats-memory.py:414-446] [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:103-109] The UAT and approved correction therefore belong after a hard session boundary and must emit only value-free booleans, counts, and digests while retaining any full drawer snapshots as private mode-controlled state. [VERIFIED: scripts/probe-solidstats-memory.py:896-953] [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:37-61]

The official tagged MemPalace v3.5.0 source confirms that `mempalace_update_drawer` requires only `drawer_id`; `content`, `wing`, and `room` are optional. Its handler fetches the existing drawer, copies the existing metadata, keeps content unless explicitly replaced, and updates only supplied wing/room fields. [CITED: https://github.com/MemPalace/mempalace/blob/v3.5.0/mempalace/mcp_server.py#L2592-L2689] [CITED: https://github.com/MemPalace/mempalace/blob/v3.5.0/mempalace/mcp_server.py#L3772-L3793]

**Primary recommendation:** Implement one exact predecessor-to-successor policy transaction with dedicated Phase 21.1 rollback state, then stop and resume in a fresh Codex session for exact-eight-tool UAT, disposable cleanup, and the single approved wing correction. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:23-61]

## Common Pitfalls

### Pitfall 1: Upgrade Path Still Requires the Retired Legacy Registration

**What goes wrong:** A reused capture/apply function rejects the real Phase 21 final state because it requires the personal `mempalace` registration. [VERIFIED: scripts/configure-solidstats-memory-client.py:398-419,623-637]

**Why it happens:** The current transaction was designed for initial replacement registration while both old and new clients coexisted. [VERIFIED: scripts/configure-solidstats-memory-client.py:782-804] [VERIFIED: .planning/STATE.md:38-50]

**How to avoid:** Create an upgrade-specific entry point that requires the exact replacement subtree and exact predecessor policy but does not require the retired legacy subtree. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:30-35]

**Warning signs:** Tests build configs with `[mcp_servers.mempalace]` even though the live precondition is legacy absence. [VERIFIED: tests/test-memory-cutover-contract.py:2617-2627]

### Pitfall 2: Exact Successor Fails the Old Forbidden Substring Check

**What goes wrong:** Adding `mempalace_update_drawer` still fails because `FORBIDDEN_TOOL_PARTS` contains `"update"`. [VERIFIED: scripts/configure-solidstats-memory-client.py:37-48,389-392]

**How to avoid:** Remove only that blanket fragment and let exact successor equality plus the remaining forbidden families enforce least privilege. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:25-32]

### Pitfall 3: Idempotency Rewrites an Already-Correct Successor

**What goes wrong:** Re-running the upgrade duplicates `enabled_tools`, changes unrelated bytes, or replaces rollback metadata unnecessarily. [VERIFIED: scripts/configure-solidstats-memory-client.py:378-395,419-445]

**How to avoid:** Treat exact successor as a successful no-op after token/subtree and file-safety validation; assert byte identity in tests. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:30-35]

### Pitfall 4: Lost Acknowledgement Leaves a Disposable Drawer

**What goes wrong:** An add/update succeeds server-side but the client sees a transport error; naive cleanup has no exact target. [VERIFIED: tests/test-memory-cutover-contract.py:2084-2140]

**How to avoid:** Inventory the chosen UAT wing before the add, use the returned exact ID when available, reconcile the poststate deterministically when acknowledgement is lost, delete exactly one identified disposable ID, and prove inventory equality. [VERIFIED: scripts/probe-solidstats-memory.py:767-816]

### Pitfall 5: Disposable UAT Pollutes the Old Wing-Empty Assertion

**What goes wrong:** The correction gate observes a leftover UAT drawer and cannot prove that active `infrastructure` is empty. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:39-47]

**How to avoid:** Complete and prove exact UAT cleanup before starting the approved correction; do not interleave the two mutation sequences. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:39-49]

### Pitfall 6: Update Read-Back Checks Only Named Fields

**What goes wrong:** A provenance or unrelated metadata change passes because the test compares only ID/wing/room/content. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:42-47]

**How to avoid:** Canonicalize and compare the complete pre/post payload after removing only the approved `metadata.wing` difference; store full payloads privately and publicize only their invariant digests. [VERIFIED: scripts/probe-solidstats-memory.py:896-953]

### Pitfall 7: Health Cleanup Destroys the Only Private Lock Copy

**What goes wrong:** Removing the stale worktree first deletes checkpoint-critical private evidence. [VERIFIED: AGENTS.md:54-74]

**How to avoid:** Retain, chmod, digest, create and verify the locator, re-read both, then remove only the stale worktree and verify its branch remains. [VERIFIED: .planning/phases/21.1-curator-update-surface/21.1-CONTEXT.md:63-68]
